# hiring-alignment-workbench
An interactive HR × AI prototype that turns ambiguous hiring requests into structured, traceable, and actionable recruitment criteria.
# 招聘对齐台使用指南

## 1 产品简介

招聘对齐台用于帮助招聘 HR 与业务方明确岗位目标、能力证据和关键取舍，并在招聘要求变化时，提示需要同步调整的寻访、候选人复核和面试工作。

当前版本为规则驱动的交互原型，适合产品演示、用户测试和面试作品展示。它不会调用真实 AI 模型，也不会自动决定候选人是否合适。

## 2 完整操作流程

### 第一步 生成岗位共识卡

1. 进入“需求与标准”。
2. 选择“二次元内容运营”示例。
3. 查看或修改业务原话。
4. 选择入职后的首要交付目标。
5. 选择能力与到岗时间之间的关键取舍。
6. 点击“写入初稿”。

产品只让用户优先完成两个会改变招聘方向的选择，用于降低一次性填写长问卷的负担。

### 第二步 审阅和确认标准

岗位共识卡包括业务目标、能力证据、协作要求、关键取舍和其他边界。每条标准均可编辑，并显示信息来源：

- `规则建议 待审阅`：由 Demo 的预设规则生成，需要人工判断。
- `HR 输入 请核实业务意见`：来自 HR 的选择或补充，仍需要业务确认。
- `HR 编辑 待确认`：HR 修改过内容，旧确认已经失效。
- `HR 确认的变更`：需求变更经过人工确认后写入。

点击“确认本条”可记录 HR 已审阅。这里的确认不等于业务方已正式签字，真实使用中仍需明确确认人和确认时间。

### 第三步 预览需求变更

1. 进入“变更影响”。
2. 查看示例业务消息：要求候选人必须具备成熟创作者资源。
3. 选择需要调整的标准。
4. 填写更新后的具体要求和要求性质。
5. 点击“预览变更影响”。

系统会展示变更前后的标准、需要重新确认的问题，以及寻访策略、候选人证据和面试材料的复核事项。预览不会修改当前版本；点击“确认并应用”后变更才会生效。应用后仍可撤销，撤销动作也会保留版本记录。

### 第四步 核验候选人证据

页面提供三份虚拟候选人材料，每份材料分别展示简历原始描述、当前能够确认的证据和仍需核实的信息。

用户可以将状态改为“待核验”“已向候选人追问”或“相关证据已核实”。产品不会生成匹配分，也不会自动淘汰候选人。简历没有描述某项经历，只能说明信息不足，不能直接判断候选人不具备该能力。

### 第五步 导出招聘材料

进入“招聘材料”，可以切换三种输出：

- **给业务确认：** 汇总岗位目标、要求、边界、确认状态和信息来源。
- **给 HR 寻访：** 提供寻访目标、搜索起点、证据要求和关键取舍。
- **给面试官：** 提供能力验证重点、针对性追问和记录方式。

点击“复制内容”可粘贴到聊天、文档或招聘台账；也可以下载为文本文件。

### 第六步 验证与复盘

“验证与复盘”页面提供三项产品假设：

1. 两次关键选择是否能降低填写负担。
2. 需求变更预览是否能减少影响项遗漏。
3. 输出材料是否能够直接进入现有工作流程。

建议邀请 3 位具有招聘或用人经验的试用者完成相同任务，记录完成用时、需要帮助的次数、遗漏的影响项和最终材料需要修改的条目。小样本结果用于发现交互问题，不应直接表述为显著提升招聘效率。

## 3 数据保存

当前版本只在浏览器当前页面保存操作状态，刷新或关闭页面后会重置。如需保留记录，请点击左侧“下载工作记录”，导出 JSON 文件。当前版本不支持重新导入、多人协作或长期存储。
